## 2. 기존 시스템 작동 원리

### 2-1. 통장적요자동생성기 (은행)
7단계 마법사: ①헤더 행 클릭 → ②날짜 열 → ③입금 열 → ④출금 열 → ⑤잔액 열 → ⑥기초잔액(첫 행에서 역산) → ⑦적요 열(여러 개, 값 제외 가능).
- 날짜가 역순이면 뒤집음, 잔액을 다시 계산해 원본 잔액과 비교(불일치 행 빨간색).
- 특수조건 사전: 토스(거래금액 단일 열 → 입금/출금 분리) 1건.
- 출력: `결제일 / 입금 / 출금 / 잔액 / (참고용)잔액 / 의뢰인/수취인` + 원본 시트.

### 2-2. 지능형금융엑셀나누기 (증권)
5단계: ①행 병합(반복 헤더 행 클릭) → ②통화별 분리(원화/외화) → ③열 매핑(사전 자동) → ④제거 항목 → ⑤입금/출금/제거 분류 + 잔액 검증.
- `BrokerAutoMapper.presets`: 증권사 37곳, 프로필(헤더 이름 목록)별로 점수를 매겨 최고점 선택. 입금·출금·제거 거래종류 목록도 사전에 포함.
- 특수 규칙: 대신(일괄매수 무시, 일괄매도 금액 대체), KB 간편 포맷(입금/출금 열 분리형).
- 잔액 흐름으로 제거 항목을 자동 추천(최대 5회 반복 최적화).
- 수수료·제세금은 별도 출금 행으로 분리.
- 출력: `일자 / 입금 / 출금 / 잔액 / (참고)원본잔액 / 적요`.

## 3. 샘플 23개 분석 결과 (핵심 근거)

| 구조 | 파일 |
|---|---|
| 1줄 헤더, 거래 1건 = 1줄 | KB국민은행, 유진, SK(제목 2줄), IBK, 교보×3, 삼성(제목 1줄), DB×2, 한화(제목 6줄+빈 줄) |
| 2줄 헤더, 거래 1건 = 2줄 | NH, 미래, KB증권, 키움, 대신(제목 1줄), 메리츠, 신한×3(제목 3줄, 헤더 3줄 중 1줄은 줄바꿈), 한투(제목 7줄) |
| 3줄 헤더, 거래 1건 = 3줄 | IM(제목 4줄) |
| 특수 | 현대차(헤더 6줄, 파일명이 `잔고증명`) |

관찰:
1. **파일명이 이미 규칙적**: `번호_기관약칭(계좌번호)_거래내역`. 기관과 계좌번호를 파일명에서 바로 얻을 수 있습니다.
2. **사전의 별칭(aliases)이 정식 명칭뿐**: `미래에셋증권`, `키움증권`처럼 등록되어 있어 파일명의 `미래`, `키움`, `한투`, `IM`, `현대차`와 일치하지 않습니다. → 파일명 가산점(+2.5)이 사실상 작동하지 않습니다.
3. **은행·증권 구분은 헤더로 가능**: 은행은 `입금액/출금액/잔액`이 별도 열, 증권은 `거래종류(구분)+거래금액+예수금`.
4. **헤더 행 수는 날짜 주기로 자동 판단 가능**: 날짜가 들어있는 행 간격(1·2·3줄)이 곧 거래 1건의 줄 수입니다. 첫 날짜 행 바로 위 N줄이 헤더입니다. 현재는 사용자가 매번 클릭합니다.
5. **현금 거래가 없는 파일**: IBK(공모주 입고·출고만, 예수금 없음) → "현금 거래 없음"으로 자동 처리하면 확인할 필요가 없습니다.
6. **KB국민은행 파일은 시트 2개**(KB1, KB2 = 서로 다른 계좌 추정)이고 사용자 분류 열(항목_대/소)이 추가되어 있습니다.

## 4. 기존 도구의 보완점

### 공통
- **결과 형식이 서로 다름**(`결제일` vs `일자`, `의뢰인/수취인` vs `적요`, 참고 열 이름도 다름).
- **SheetJS를 버전 없이 unpkg에서 불러옴**(`unpkg.com/xlsx`). 버전이 바뀌거나 끊기면 작동하지 않습니다. auto-classifier처럼 로컬 파일(`xlsx.full.min.js`)로 고정해야 합니다.
- **사전 수정 = 코드 수정**. 실수하면 프로그램 전체가 멈출 수 있고 백업 파일이 계속 늘어납니다(versions 36개).

### 통장적요자동생성기
- 금액을 읽지 못하면 0으로 처리(`parseFloat(...) || 0`) → 지침 위반, 누락을 숨길 수 있음.
- 미리보기 표에 원본 셀 값을 그대로 HTML로 넣음(escape 미적용) → 특수문자가 있는 적요에서 표가 깨질 수 있음.
- 헤더·열 선택이 전부 수동, 은행별 사전 없음(토스 1건).
- 날짜 열에서 날짜를 못 읽은 행은 조용히 버려짐(경고 없음).

### 지능형금융엑셀나누기
- 같은 이름의 함수가 여러 번 재정의됨(`classifyByBalance`, `handleBalanceMismatchRestart`, 단계 렌더링 등). 어떤 코드가 실제로 실행되는지 추적하기 어렵습니다 → 통합 시 UI를 복사하지 말고 **엔진(사전·변환·검증)만 분리 이식**하는 것이 안전합니다.
- 행 병합이 수동이고, "헤더 행 수 = 거래 1건 줄 수"를 가정 → 신한(헤더 3줄, 거래 2줄)은 사용자가 정확히 2줄만 골라야 함.
- 사전 별칭에 약칭 누락(위 3번 항목).

## 6. 올인원 구조 제안

### 처리 흐름
```
[여러 파일 / 폴더 드래그]
   │
① 파일명 해석 ── 기관 약칭, 계좌번호, 번호 추출 (예: 12_KB(123-456-789-01) → KB, 123-456-789-01)
② 시트 정리 ─── 제목·조회조건 행 제거, 날짜 주기로 헤더 줄 수·거래 줄 수 자동 판정 → 1행 1거래로 평탄화
③ 유형 판별 ─── 은행형(입금/출금 분리 열) / 증권형(거래종류+금액+예수금)
                + 기관 사전 매칭(파일명 약칭 + 헤더 점수)
④ 변환 ──────── 은행형: 입금·출금·잔액 바로 매핑, 적요 열 자동 선택
                증권형: 기존 증권 엔진(분류·수수료 분리·제거 추천) 이식
⑤ 잔액 검증 ─── 기초잔액 + 입금 − 출금 = 원본 잔액 (행마다)
   │
[결과 대시보드]
   ● 초록: 자동 완료 (잔액 일치) → 확인 불필요
   ● 노랑: 확인 필요 (사전 미등록 거래종류, 판별 점수 낮음)
   ● 빨강: 실패 (잔액 불일치, 날짜·금액 읽기 실패)
   ● 회색: 현금 거래 없음 (입고/출고만)
   │
노랑·빨강만 수정 화면 열기 (기존 마법사와 같은 방식, 자동 결과가 미리 채워짐)
   │
수정 내용 → "사전에 반영" → 기관사전.json 갱신 (다음 달부터 자동)
   │
[일괄 다운로드] 계좌별 시트(날짜/입금/출금/잔액/적요) + 요약 시트 + 원본 시트
```

### 핵심 아이디어 5가지
1. **파일명 우선 판별**: 약칭 표(`미래→미래에셋증권`, `한투→한국투자증권`, `KB→은행/증권은 헤더로 구분` 등)를 사전에 추가. 은행·증권 이름이 겹치는 KB·신한·NH·IBK는 헤더 유형으로 최종 결정합니다.
2. **헤더 자동 감지**: 날짜로 읽히는 첫 열 값의 행 간격으로 거래 줄 수를 정하고, 그 위 줄들을 헤더로 합칩니다. 줄바꿈된 헤더(신한 `예탁금`+`이용료`)는 위 칸과 이어 붙입니다.
3. **사전을 코드 밖으로**: `dictionary/기관사전.json`으로 분리. 화면에서 "사전 반영"을 누르면 Edge/Chrome 파일 저장 기능으로 같은 폴더에 저장(저장 전 이전 사전 자동 백업). 지원되지 않는 브라우저에서는 내려받기로 대체.
4. **계좌 기억**: 계좌번호별로 마지막 설정(열 매핑, 제외 적요, 분류)을 사전에 저장 → 같은 계좌는 다음 달부터 완전 자동.
5. **은행도 사전 적용**: 은행별 프로필(KB국민, 신한, 우리, 하나, 농협, 기업, 토스 등)을 증권과 같은 구조로 등록. 기존 토스 특수조건도 여기로 이동.

### 폴더 구성(예정)
```
증권및은행통장내역편집기/

├─ instructions/           ← 적용 지침 사본
```

## 8. 결정 사항 (2026-11-10 사용자 확정)
1. 결과 형식: **수지라 업로드용 유지** — `결제일 / 입금 / 출금 / 잔액 / (참고용)잔액 / 의뢰인/수취인`.
2. 증권 수수료·제세금: **지금처럼 별도 출금 행**.
3. 사전 저장 위치: **이 폴더**(`dictionary/`).
4. 잔고증명 등 거래내역이 아닌 파일: **자동 제외하지 않음** (판별 결과만 표시).
