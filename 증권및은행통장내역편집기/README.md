# 통합 통장내역 편집기

은행·증권 통장 엑셀을 한꺼번에 올리면 **은행/증권 구분, 기관, 표 구조를 자동으로 판별**하고
수지라 업로드 형식(`결제일 / 입금 / 출금 / 잔액 / (참고용)잔액 / 의뢰인/수취인`)으로 변환합니다.
계산한 잔액을 원본 잔액과 맞춰 보고, 맞지 않는 계좌만 열어서 고치면 됩니다.

- 설치 없이 브라우저(Edge, Chrome)에서 동작합니다. 인터넷 연결도 필요 없습니다.
- 올린 엑셀은 **내 컴퓨터 브라우저 안에서만 처리**됩니다. 어디에도 전송·저장되지 않습니다.
- 새로고침하면 작업 내용이 모두 사라집니다. 필요한 결과는 다운로드하세요.

## 사용 방법

1. `index.html`을 엽니다 (GitHub Pages 주소 또는 내려받은 폴더의 파일).
2. 통장 엑셀 파일을 화면에 끌어 놓습니다. 여러 파일, 여러 시트를 한 번에 올릴 수 있습니다.
   - 파일명이 `번호_기관약칭(계좌번호)_거래내역.xlsx` 형식이면 기관·계좌를 파일명에서 읽습니다. (예: `12_KB(123-456-789-01)_거래내역.xlsx`)
   - 계좌번호가 없어도 됩니다. 계좌 이름은 파일명(시트가 여러 개면 파일명 + 시트명)으로 붙습니다.
3. 목록의 상태를 봅니다.

   | 상태 | 뜻 | 할 일 |
   |---|---|---|
   | 자동 완료 | 계산 잔액 = 원본 잔액 | 없음 |
   | 확인 필요 | 사전에 없는 형식, 잔고증명 파일 등 | 열어서 확인 |
   | 잔액 불일치 | 계산 잔액 ≠ 원본 잔액 | 열어서 수정 |
   | 현금거래 없음 | 주식 입고·출고만 있음 | 없음 (입출금외 내역에 보관됨) |

4. 확인이 필요한 행을 누르면 아래에 편집 화면이 열립니다.
   - **계좌명**: 다운로드 파일의 시트 이름
   - **열 지정**: 날짜·금액·잔액 등을 어느 열에서 읽을지
   - **기초잔액**: 자동 계산(첫 거래에서 역산) 또는 직접 입력
   - **증권 – 거래종류 분류**: 입금 / 출금 / 제거(입출금외) / 미분류
   - **증권 – 수수료·제세금**: 별도 출금 행으로 분리(기본) 또는 거래금액에 포함
   - **은행 – 적요 열**: 여러 열을 고르면 " / "로 합침, 뺄 값 지정 가능
   - 빨간 줄은 계산 잔액과 원본 잔액이 다른 곳입니다.
5. **엑셀 다운로드**를 누르면 다음 시트가 담긴 파일을 받습니다.
   - `요약`: 계좌별 건수, 기초·기말 잔액, 차이, 상태
   - `입출금외내역`: 입출금에 영향이 없는 거래(공모주 입고, 타사대체 출고 등). 적요에 수량×단가 금액이 붙습니다.
   - 계좌별 결과 시트 (수지라 업로드 형식)
   - (선택) `원본_계좌명`: 한 줄로 정리한 원본

## 사전 (자동 판별 규칙)

`dictionary/institutions.js`에 증권사·은행별 열 이름, 거래종류 분류, 적요 열, 수수료 처리 방식, 파일명 약칭이 들어 있습니다.
**계좌번호·고객명·금액은 사전에 저장하지 않습니다.**

- 국내 계좌와 해외(외화) 계좌는 **사전이 따로** 있습니다. 파일명에 "해외"·"외화"가 있으면 해외 사전만 씁니다.
- 거래종류 분류는 **증권사 단위로도** 기억합니다. 같은 증권사의 새 양식(열 이름이 다른 파일)이라도 열만 지정하면 그 증권사에서 배운 분류를 씁니다.
- 해외 계좌 파일에 원화와 외화 거래가 섞여 있으면 **통화별 계좌로 나눕니다**(예: `…[KRW]`, `…[USD]`). 환전 거래는 두 계좌 모두에 들어갑니다(원화 입금 + 외화 출금). 나누는 방법은 증권사 형식별로 사전에 적혀 있어야 하며, 없으면 나누지 않고 "확인 필요"로 둡니다.
- 외화 계좌는 0.01(센트) 단위까지, 원화는 1원 단위로 잔액을 검증합니다. 같은 날 안의 순서 차이는 그날 마지막 잔액으로 판정합니다.
- 정산금액 열이 있으면 수수료·세금 외의 숨은 비용을 "(기타비용)" 출금 행으로 넣습니다.
- 원본 파일에 거래가 빠져 잔액이 맞지 않을 때는 편집 화면의 **"날짜별 잔액 차이를 (잔액보정) 행으로 맞추기"**로 맞출 수 있습니다. 이 경우 "확인 필요"로 표시됩니다.
- **예외 규칙**: 한 건의 사례에서 나온 처리 방법은 "예외 규칙"으로 따로 둡니다. 그 사례 파일과 **열 이름이 모두 같은 파일에만** 적용되고, 이때 입금/출금은 사전 목록이 아니라 **잔액 변화로** 분류합니다. 화면의 판별 근거에 "예외 규칙 …(사례 N건)"이 표시됩니다.
- **순서가 섞인 파일**(위→아래·아래→위가 섞였거나 같은 날 안 순서가 뒤바뀐 파일)은 잔액이 이어지도록 자동으로 순서를 복원합니다. 원본 순서로 잔액이 맞지 않을 때만 시도하고, 잔액이 더 잘 맞을 때만 적용합니다. 편집 화면 "날짜 순서"에서 "날짜순만(복원 안 함)"을 고르면 끌 수 있습니다.
- **적요에서 뺄 값**: 편집 화면의 적요 열마다 탭이 있고, 그 열의 값이 건수와 함께 "포함될 내용 / 제외될 내용"으로 나옵니다. 값을 누르면 옮겨집니다(그 열에서만). 값이 많으면 "값 찾기"로 좁히세요.
- **증권 추가 적요**: 열 지정의 "추가 적요 1·2"를 고르면 적요 끝에 " / 값"으로 붙고, 같은 방식으로 뺄 값을 고를 수 있습니다. "사전에 반영"하면 같은 형식 파일에 자동 적용됩니다.
- **예외 규칙 계좌에서 거래종류가 "입출금"처럼 하나로 되어 있으면**, 행마다 잔액 변화로 "[입금]"/"[출금]"을 나눕니다. 잔액으로 정할 수 없는 행(첫 거래 등)은 "[방향 미확인]"으로 두고 확인 필요로 보냅니다 — 기초잔액을 입력하면 정해집니다.
- **거래종류 근거**: 증권 계좌의 거래종류 분류 칸마다 "건수 · 사전 분류 · 잔액 확인 입금/출금 N건"이 표시됩니다. 잔액 변화와 반대로 분류된 칸은 빨간 테두리로 표시됩니다. 사전에 없지만 잔액으로 방향이 확인된 분류는 "사전 반영 후보"로 묶어 보여 줍니다(거래처·이름이 들어 있을 수 있는 긴 거래종류는 후보에서 뺌).
- **기관 고르기**: 편집 화면의 기관 칸에 글자를 치면 사전의 기관 목록(국내·해외 증권사, 은행)이 나옵니다. 고르면 그 기관의 형식으로 다시 판별해 열을 채웁니다(열 지정·분류는 새로 계산). 목록에 없는 이름을 넣으면 경고합니다 — 오타로 사전에 기관이 따로 생기지 않게 목록에서 고르세요.
- **형식 이름**: 한 기관에 양식이 여러 개면 "형식1, 형식2…"로 따로 기억합니다. 편집 화면 "사전 형식" 칸에서 이름(예: HTS 거래내역)을 붙일 수 있고, "사전에 반영"으로 새 형식이 생길 때도 이름을 묻습니다. 바꾼 이름은 "사전 파일 저장"으로 팀에 공유합니다.
- **계좌 지우기**: 목록 맨 오른쪽 ×(한 개), 체크 후 "선택 삭제", 편집 화면 "이 계좌 삭제"·"같은 파일 모두 삭제". 직접 고친 계좌는 확인을 묻고, 지운 직후 상태 줄의 "되돌리기"로 살릴 수 있습니다. "목록 비우기"도 되돌릴 수 있습니다.
- 확장자는 .xls 인데 실제로는 웹페이지인 파일(증권사 홈페이지 저장 등)은 제목만 있는 표를 따로 계좌로 만들지 않습니다.
- **잔액 열이 없는 증권 파일**(홈페이지·앱 간편 조회 등)도 처리합니다. "입출금 구분" 열(예: 거래구분 = 입금/출금)과 사전으로 입금·출금을 나누고, 기초잔액(전월 말 잔액)을 넣으면 잔액이 계산됩니다. 원본 잔액이 없어 검증은 할 수 없으므로 항상 "확인 필요"로 표시됩니다 — 내용을 보고 "확인 완료"를 누르세요. 계산 잔액이 음수가 되면 수수료 처리(포함/별도)나 기초잔액을 확인하라는 안내가 나옵니다.
- **머리글이 여러 칸에 병합된 파일**(예: "거래종류" 머리글 아래 순번 칸 + 이름 칸)은 순번 칸이 아니라 글자가 있는 칸을 그 열로 읽습니다.
- **거래처 이름이 붙은 거래종류**(예: 한화 "[입금] 은행이체입금(국민은행 ○○)")는 사전에 **앞부분만** "[입금] 은행이체입금(…)"으로 저장합니다. 다른 거래처의 같은 거래에도 같은 분류가 적용되고, 사전(공개 저장소)에 거래처 이름이 남지 않습니다. (외화)·(이자)처럼 짧은 구분어는 그대로 둡니다.
- **입출금외(제거) 거래에 붙은 수수료**(예: 주식 타사대체출고 수수료)는 잔액이 실제로 그만큼 줄었으면 "(입출금외 거래 비용)" 출금 행으로 결과에 넣습니다. 제거로 분류한 거래에서 잔액이 설명 없이 바뀌면 "확인 필요"로 알려 줍니다.
- 사전 파일에 오류가 있으면 불러오지 않고 지금 쓰던 사전을 그대로 씁니다. 배포된 사전이 깨져 있으면 화면은 빈 사전으로 계속 동작하고 빨간 안내를 띄웁니다.

### 새 형식을 사전에 추가하기 (누구나)
1. 계좌를 편집해 잔액이 맞게 만든 뒤 **"이 설정을 사전에 반영"**을 누릅니다.
2. 같은 기관·같은 파일 형식의 다른 계좌도 바로 다시 판별됩니다. 이 변경은 지금 브라우저에만 있습니다.
3. **"사전 파일 저장"**을 눌러 `institutions.js`를 내려받아 관리자에게 전달합니다.

### 팀 전체에 적용하기 (관리자)
1. 받은 `institutions.js`를 먼저 검사합니다: `npm run check-dictionary -- 받은파일경로` (오류 0건이어야 함). 그다음 저장소의 `dictionary/institutions.js`를 교체합니다.
2. 변경 내용은 파일 안 `changelog`에 남아 있습니다. GitHub의 변경 비교(diff)로도 확인할 수 있습니다.
3. 커밋·푸시하면 GitHub Pages에 반영됩니다. 팀원은 새로고침만 하면 됩니다.
- 올리기 전 테스트해 보려면 **"사전 불러오기"**로 받은 파일을 열어 보세요. 새로고침하면 배포된 사전으로 돌아갑니다.

### 로컬에서 바로 프로젝트 사전에 저장하기(관리자, Edge·크롬)
- 이 폴더의 index.html 을 로컬에서 열면 사전 줄에 **"프로젝트 사전 폴더 연결"** 단추가 보입니다. 처음 한 번 프로젝트의 `dictionary` 폴더를 고르고 "허용"을 누르면 연결됩니다(다음에도 기억).
- 연결된 동안에는 "이 설정을 사전에 반영"·형식 이름 변경이 **`dictionary/institutions.js` 에 바로 저장**됩니다(다운로드 없음). 저장 전 이전 사전은 `dictionary/_backup/institutions_시각.js` 로 백업되고, 상태 줄의 "되돌리기"로 방금 저장을 취소할 수 있습니다.
- 그 사이 파일이 다른 경로(사전 가져오기 등)로 바뀌었으면 덮어쓰지 않고 새로고침을 안내합니다. "사전 불러오기"로 다른 사전을 쓰는 중에는 저장하지 않습니다.
- GitHub 사이트에서는 이 단추가 나오지 않습니다(팀원은 "사전 파일 저장"으로 내려받아 관리자에게 전달).

### 로컬에서 반영한 사전을 프로젝트 사전에 넣기(관리자)
- 화면의 "사전에 반영"은 브라우저 안에서만 적용되고, "사전 파일 저장"은 다운로드 폴더에 institutions.js 를 내려받습니다(프로젝트 파일은 그대로).
- 내려받은 사전을 프로젝트에 넣으려면 `사전가져오기.cmd` 를 더블클릭하거나 `npm run import-dictionary` 를 실행합니다. 바뀌는 내용(추가·변경·사라짐)을 먼저 보여 주고 확인을 받은 뒤, 지금 사전을 version/ 에 백업하고 교체합니다. 지금 사전에만 있는 내용이 사라지거나 더 오래된 사전이면 경고하고 멈춥니다.

## GitHub에 올리는 파일
- **꼭 필요(프로그램 실행)**: `index.html`, `lib/xlsx.full.min.js`, `dictionary/institutions.js`, `engine/` 4개(`engine.js`, `convert.js`, `dictionary.js`, `securities-legacy.js`), `README.md`(사용설명서)
- **관리용(권장)**: `.gitignore`, `package.json`, `package-lock.json`, `tools/`, `tests/`(스크립트만), `AGENTS.md`, `개발구성.md`, `HISTORY.md`, `HANDOFF.md`, `개선제안서.md`
- **공개 저장소라면 빼는 것을 권장**: `instructions/`(사내 작업 지침), `reference/`(기존 도구 원본 사본 — 증권 엔진을 다시 만들 때만 필요)
- **절대 올리지 않음(.gitignore 로 제외)**: 고객 엑셀(`*.xlsx`·`*.xls`·`*.csv`), `tests/expected*.json`, `cases/`, `version/`, `tests/output/`, `node_modules/`
- 올리기 전: `npm run check-dictionary`, `npm run check-publish`(고객 정보 없음 확인)

## GitHub Pages 배포 (관리자, 최초 1회)
1. 저장소 Settings → Pages → Source: `Deploy from a branch`, Branch: `main` / `(root)`
2. 표시되는 주소(`https://<계정>.github.io/<저장소>/`)를 팀에 공유합니다.
- 필요한 파일은 `index.html`, `lib/`, `dictionary/`, `engine/`입니다. 이 네 가지는 같은 폴더 구조로 함께 있어야 합니다.
